## Usage

Use a full-screen page for views that need all of the space, such as a layout editor or a preview, and that people open from another page and close again. Without the navigation and the frame, the content fills the shell, and the close button of [**Page**](/components/page) at the start of the header leads back.

The `start` and `end` slots of **Page** hold the tools of the view, here the layers and the properties of a layout. Each [**Panel**](/components/panel) is `resizable` and `closable`, so people can make room for the content. With `inset`, the content has no padding, for example for a canvas. In the mobile layout of the page, the panels turn into drawers that open from the header.

Keep the shell with its navigation in the root component of your application, and hide its regions in the meta of the full-screen route. The shell reads the meta before the page renders, so the navigation doesn't flicker during the transition.

```ts
const routes = [
  {
    path: "/shopping-experiences/:id",
    component: LayoutEditorView,
    meta: {
      mtAppRegions: { header: false, navigation: false, sidebar: false, contentFrame: false },
    },
  },
];
```

To switch a view into full screen and back while it stays open, call [`useAppRegions()`](/utilities/composables/use-app-regions) in the view instead. Replace the `placeholder-slot`s with the actions, the content and the panels of your view.

## Components

- [**App**](/components/app) for the shell
- [**Page**](/components/page) for the page with the close button and the panels
- [**Panel**](/components/panel) for the layers and the properties
