Meteor ships English and German texts for all components and doesn't depend on any i18n
library. Without any setup, components render in English.

## Choose your setup

- **English is enough:** nothing to do.
- **Your app uses vue-i18n:** connect it with [`createVueI18nAdapter`](#vue-i18n).
- **Your app knows its language some other way** (the Admin SDK, a language switcher, ...):
  [pass the language as a ref](#language-from-your-app).
- **Your app uses another translation library for Meteor's texts:**
  [write a small adapter](#other-translation-libraries).

## vue-i18n

Meteor follows the language of your vue-i18n instance, and `mt.*` keys in your vue-i18n
messages [override Meteor's texts](#override-texts-or-add-a-language):

```ts
import { createApp } from "vue";
import { createI18n } from "vue-i18n";
import {
  createMeteorI18nPlugin,
  createVueI18nAdapter,
} from "@shopware-ag/meteor-component-library";
import App from "./App.vue";

const i18n = createI18n({ legacy: false, locale: "en", messages });

createApp(App)
  .use(i18n)
  .use(createMeteorI18nPlugin({ adapter: createVueI18nAdapter(i18n) }))
  .mount("#app");
```

- `legacy: false` is required. In legacy mode, Meteor can't follow language changes (it
  warns about this in development).
- Pass the global instance (the `createI18n()` result or `i18n.global`), not a component's
  own `useI18n()`.

**Iframe apps in the Shopware Administration** get the language from the Admin SDK. Drive your
vue-i18n instance with it:

```ts
import { context } from "@shopware-ag/meteor-admin-sdk";

const { locale, fallbackLocale } = await context.getLocale();
const i18n = createI18n({ legacy: false, locale, fallbackLocale, messages });

void context.subscribeLocale((next) => {
  i18n.global.locale.value = next.locale;
  i18n.global.fallbackLocale.value = next.fallbackLocale;
});
```

## Language from your app

If your app has no translation library, pass the language as a ref. Meteor renders its own
texts in that language and follows when the ref changes:

```ts
import { ref } from "vue";
import { createMeteorI18nPlugin } from "@shopware-ag/meteor-component-library";

const locale = ref("de-DE");

app.use(createMeteorI18nPlugin({ locale }));

// later
locale.value = "en-GB";
```

**Iframe apps in the Shopware Administration** fill the ref from the Admin SDK. Read the
language before mounting, otherwise the app briefly shows English:

```ts
import { createApp, ref } from "vue";
import { context } from "@shopware-ag/meteor-admin-sdk";
import { createMeteorI18nPlugin } from "@shopware-ag/meteor-component-library";
import App from "./App.vue";

const { locale: initialLocale } = await context.getLocale();
const locale = ref(initialLocale);

void context.subscribeLocale((next) => {
  locale.value = next.locale;
});

createApp(App).use(createMeteorI18nPlugin({ locale })).mount("#app");
```

When your app gets texts of its own later, hand the same ref to vue-i18n and switch to
`createVueI18nAdapter`.

## Other translation libraries

An adapter connects any other library. It has two required parts:

- `locale`: the current language as a ref, computed or getter.
- `t(key, values, options)`: returns the text, or `undefined` if there is none. Never return
  the key itself, otherwise Meteor can't fall back to its own text. When `options.locale` is
  set, look only in that language. Read the current language inside `t`, so components update
  when it changes.

`n(value)` for number formatting is optional; without it, Meteor uses `Intl.NumberFormat`.

```ts
import { ref } from "vue";
import { createMeteorI18nPlugin } from "@shopware-ag/meteor-component-library";

const locale = ref("de-DE");
const texts: Record<string, Record<string, string>> = {
  "de-DE": { "mt.pagination.nextPage": "Weiter" },
};

app.use(
  createMeteorI18nPlugin({
    adapter: {
      locale,
      t: (key, _values, options) => texts[options?.locale ?? locale.value]?.[key],
    },
  }),
);
```

## Override texts or add a language

Every Meteor text has a public key, `mt.<component>.<key>`, for example `mt.pagination.nextPage`
or `mt.field-error.INVALID_MAIL`. You find the keys and their texts in the component's source.
When you override a text, keep its placeholders, e.g. `{start}`, `{end}` and `{totalItems}` in
`mt.pagination.infoText`.

**In your translation solution** (vue-i18n, the Shopware Administration's snippet files, ...),
add the key as nested JSON:

```json
{ "mt": { "pagination": { "nextPage": "Weiter" } } }
```

In the Shopware Administration, plugins add these keys to their regular snippet files.

Add the override for every language you support. An override that only exists in English isn't
used for German; there, Meteor's own German text wins.

**Without a translation solution**, use the plugin's `messages` option. Keys can be flat or
nested; a region code like `de-AT` falls back to `de`, then to English:

```ts
app.use(
  createMeteorI18nPlugin({
    messages: {
      fr: {
        "mt.pagination.nextPage": "Suivant",
        "mt.pagination.previousPage": "Précédent",
      },
      "en-US": {
        "mt.pagination.nextPage": "Next",
      },
    },
  }),
);
```

## Lookup order

For every text, Meteor uses the first match:

1. your translation in the current language,
2. Meteor's text in the current language (overrides from `messages` win over the built-in ones),
3. your translation in the fallback language,
4. Meteor's English text,
5. the key itself.

## Notes

- **vue-i18n versions:** tested with v10 and v11; v11.4.9 or newer is recommended.
- **Flat keys in vue-i18n:** before v11.3, vue-i18n can't find flat dotted keys like
  `"mt.pagination.nextPage": "..."`. Use nested JSON, `flatJson: true`, or
  `createVueI18nAdapter(i18n, { skipExistenceCheck: true })`. The last option is also needed
  when your translations come from vue-i18n's `missing` handler.
- **Special characters:** `{ } @ $ |` in your vue-i18n messages need vue-i18n's escaping. Texts
  in the `messages` option don't. If a text can't be compiled, Meteor falls back to its own text
  and warns in development.
- **Old key names:** keys from Meteor 5 (`mt-field-error.*`, `mt-text-editor*.*`,
  `mt-action-menu-item.*`) keep working with `createVueI18nAdapter(i18n, { legacyKeys: true })`.
  Development builds warn once per key.
- **Plurals:** Meteor's own texts use the English/German rule (`"one item | {n} items"`). Provide
  texts for languages with more plural forms through your translation solution.
- Don't render translated texts with `v-html`; values aren't HTML-escaped.

## Inside Meteor components

Meteor's components translate their texts with the
[`useMeteorI18n` composable](/utilities/composables/use-meteor-i18n). Use it for custom
components that should translate the same way.
