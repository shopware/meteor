title: Internationalization
description: How Meteor components translate their texts, how to connect your app's language, and how to change Meteor's texts or add languages.

Meteor components come with English and German texts and don't need an i18n library. Without
any setup, they show English.

## Choose your setup

### Shopware plugins

- Meteor components already show the language the user picked in the Administration. There's
  nothing to set up.
- To change one of Meteor's texts, add its key to your plugin's snippet files. See
  [Change texts or add a language](#change-texts-or-add-a-language).

### Shopware apps & services

- Apps run in their own iframe and get the Administration's language from the Admin SDK.
- If your app translates its own texts with vue-i18n, connect it to Meteor once. Meteor
  components then follow the Administration's language too. See
  [Connect vue-i18n](#connect-vue-i18n).

### Standalone applications

- Without any setup, Meteor components show English.
- If your app supports more languages, connect its translations to Meteor. See
  [Connect vue-i18n](#connect-vue-i18n) or
  [Connect another translation library](#connect-another-translation-library).

## Connect vue-i18n

Connect your vue-i18n instance once. Meteor components then switch language together with your
app, and you can change Meteor's texts in your vue-i18n messages.

**In a Shopware app or service**, take the language from the Admin SDK:

```ts
import { createApp } from "vue";
import { createI18n } from "vue-i18n";
import { context } from "@shopware-ag/meteor-admin-sdk";
import {
  createMeteorI18nPlugin,
  createVueI18nAdapter,
} from "@shopware-ag/meteor-component-library";
import App from "./App.vue";

const { locale, fallbackLocale } = await context.getLocale();
const i18n = createI18n({ legacy: false, locale, fallbackLocale, messages });

// Follow when the user switches the Administration's language.
void context.subscribeLocale((next) => {
  i18n.global.locale.value = next.locale;
  i18n.global.fallbackLocale.value = next.fallbackLocale;
});

createApp(App)
  .use(i18n)
  .use(createMeteorI18nPlugin({ adapter: createVueI18nAdapter(i18n) }))
  .mount("#app");
```

**In a standalone application:**

```ts
const i18n = createI18n({ legacy: false, locale: "en", messages });

createApp(App)
  .use(i18n)
  .use(createMeteorI18nPlugin({ adapter: createVueI18nAdapter(i18n) }))
  .mount("#app");
```

Create vue-i18n with `legacy: false`; in legacy mode, Meteor can't follow language changes.
Meteor is tested with vue-i18n 10 and 11.

## Connect another translation library

If you use a different library, such as i18next, give Meteor a small adapter. It tells Meteor the
current language and looks up Meteor's texts in your library:

```ts
app.use(
  createMeteorI18nPlugin({
    adapter: {
      locale, // the current language, e.g. a ref
      t: (key, values, options) => lookUpInYourLibrary(key, values, options?.locale),
    },
  }),
);
```

- `locale` is the current language: a ref, a computed or a function.
- `t` returns the text for a key, or `undefined` if your library doesn't have it. Meteor then
  uses its own text, so never return the key itself. If Meteor passes a language in
  `options.locale`, look only in that language.
- Read the current language inside `t`, so the texts change when the language changes.
- Optionally, add `n(value)` to format numbers. Without it, Meteor uses the browser's number
  format for the current language.

## Use Meteor without a translation library

An app without texts of its own doesn't need vue-i18n. Tell Meteor the language with a ref, and
Meteor shows its own texts in that language.

In a Shopware app or service, fill the ref from the Admin SDK. Read the language before mounting
the app, otherwise it briefly shows English:

```ts
import { createApp, ref } from "vue";
import { context } from "@shopware-ag/meteor-admin-sdk";
import { createMeteorI18nPlugin } from "@shopware-ag/meteor-component-library";
import App from "./App.vue";

const { locale: initialLocale } = await context.getLocale();
const locale = ref(initialLocale);

void context.subscribeLocale((next) => {
  locale.value = next.locale;
});

createApp(App).use(createMeteorI18nPlugin({ locale })).mount("#app");
```

When your app gets texts of its own later, hand the same ref to vue-i18n and
[connect vue-i18n](#connect-vue-i18n).

## Change texts or add a language

Every Meteor text has a key, like `mt.pagination.nextPage`. You find the keys and texts in the
`messages` of each component's
[source code](https://github.com/shopware/meteor/tree/main/packages/component-library/src/components).
Keep the placeholders of a text, e.g. `{start}`, `{end}` and `{totalItems}` in
`mt.pagination.infoText`.

**Shopware plugins** add the key to their snippet files, for example `de-DE.json`:

```json
{ "mt": { "pagination": { "nextPage": "Weiter" } } }
```

**Apps with vue-i18n** add the key to their vue-i18n messages in the same nested form.

**Apps without a translation library** use the `messages` option. Codes with a region, like
`de-AT`, also use the texts for `de`:

```ts
app.use(
  createMeteorI18nPlugin({
    messages: {
      fr: {
        "mt.pagination.nextPage": "Suivant",
        "mt.pagination.previousPage": "Précédent",
      },
    },
  }),
);
```

Add your text for every language you support. If it only exists in English, German users still
see Meteor's German text. For languages with more than two plural forms, like Polish, provide
plural texts through your translation library; the `messages` option only knows the
English/German rule.

## Which text Meteor shows

Meteor uses the first text it finds:

1. your text in the user's language,
2. Meteor's text in the user's language,
3. your text in the fallback language (English in the Shopware Administration),
4. Meteor's English text,
5. the key itself.

## Troubleshooting

- **Meteor stays English while your app switches language:** check that the Meteor plugin is
  installed and that vue-i18n uses `legacy: false`.
- **Your vue-i18n text for a Meteor key doesn't show:** write the key nested, as in
  `{ "mt": { "pagination": { ... } } }`. vue-i18n before 11.3 doesn't find flat keys like
  `"mt.pagination.nextPage"`. If your texts come from vue-i18n's `missing` handler, use
  `createVueI18nAdapter(i18n, { skipExistenceCheck: true })`.
- **A text with `{`, `}`, `@`, `$` or `|` shows up wrong or not at all:** vue-i18n needs these
  characters escaped. If vue-i18n can't read the text, Meteor shows its own text and warns in
  development.
- **Texts with Meteor 5 keys** (`mt-field-error.*`, `mt-text-editor*.*`,
  `mt-action-menu-item.*`) no longer apply: rename them to `mt.field-error.*` and so on, or keep
  them working with `createVueI18nAdapter(i18n, { legacyKeys: true })`.

## Translate your own components

Custom components can translate their texts the same way as Meteor's, with the
[`useMeteorI18n` composable](/utilities/composables/use-meteor-i18n).
