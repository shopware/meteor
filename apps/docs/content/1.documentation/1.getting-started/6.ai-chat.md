Meteor's AI components display what the [AI SDK](https://ai-sdk.dev) produces, with props shaped like its message parts. Meteor doesn't depend on the AI SDK: install `ai` and `@ai-sdk/vue` in your app and pass their data straight to the components.

## The chat

`useChat()` holds the conversation. [**Conversation**](/components/conversation) lists its messages and keeps the [**Prompt Field**](/components/prompt-field) below them. The prompt's `status` takes the chat's `status` as it is.

```vue
<script setup lang="ts">
import { useChat } from "@ai-sdk/vue";
import {
  MtConversation,
  MtPromptField,
  MtTextShimmer,
  type MtPromptFieldMessage,
} from "@shopware-ag/meteor-component-library";

const { messages, status, sendMessage, stop } = useChat();

function send({ text }: MtPromptFieldMessage) {
  void sendMessage({ text });
}
</script>

<template>
  <mt-conversation>
    <ChatMessage v-for="message in messages" :key="message.id" :message="message" />

    <template #status>
      <mt-text-shimmer v-if="status === 'submitted' || status === 'streaming'" size="xs">
        Generating response…
      </mt-text-shimmer>
    </template>

    <template #footer>
      <mt-prompt-field :status="status" @submit="send" @stop="stop" />
    </template>
  </mt-conversation>
</template>
```

## Rendering the parts of a message

A message is a list of parts. Loop over them in order and render each with the component for its type:

| Part                         | Component                                                                    | Fields                                                          |
| ---------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `text`                       | [**Markdown**](/components/markdown)                                         | `text` as `content`, `streaming` while its `state` is `streaming` |
| `reasoning`                  | [**Reasoning**](/components/reasoning)                                       | `text` as `content`, `streaming` while its `state` is `streaming` |
| `tool-*`, `dynamic-tool`     | [**Tool**](/components/tool)                                                 | `type`, `state`, `toolName`, `input`, `output`, `errorText`     |
| `tool-*` with an `approval`  | [**Confirmation**](/components/confirmation)                                 | `approval`, `state`                                             |
| `file`                       | [**Attachment**](/components/attachment)                                     | `url`, `mediaType`, `filename` as `label`                       |

```vue
<template>
  <mt-message :from="message.role">
    <template v-for="(part, index) in message.parts" :key="index">
      <mt-reasoning v-if="part.type === 'reasoning'" :streaming="part.state === 'streaming'">
        <mt-reasoning-trigger />
        <mt-reasoning-content :content="part.text" />
      </mt-reasoning>

      <mt-tool v-else-if="part.type.startsWith('tool-')">
        <mt-tool-header :type="part.type" :state="part.state" />
        <mt-tool-content>
          <mt-tool-input :input="part.input" />
          <mt-tool-output :output="part.output" :error-text="part.errorText" />
        </mt-tool-content>
      </mt-tool>

      <mt-markdown
        v-else-if="part.type === 'text'"
        :content="part.text"
        :streaming="part.state === 'streaming'"
      />
    </template>
  </mt-message>
</template>
```

A stopped answer keeps the state its parts had, such as a `streaming` reasoning part. Set `streaming` only while the chat's `status` is still `streaming`, too.

## Approvals

A tool that needs approval stops in the `approval-requested` state. Show a [**Confirmation**](/components/confirmation) below it and answer with `addToolApprovalResponse()`. With `sendAutomaticallyWhen`, the answer continues on its own once every approval is given:

```ts
import { lastAssistantMessageIsCompleteWithApprovalResponses } from "ai";

const { addToolApprovalResponse } = useChat({
  sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithApprovalResponses,
});

function answer(approvalId: string, approved: boolean) {
  void addToolApprovalResponse({ id: approvalId, approved });
}
```

## Retry, errors and feedback

- Put [**Message Actions**](/components/message-actions) at the end of the last answer: copy its text, retry with `regenerate()`, and rate it.
- When `error` is set, show a [**Banner**](/components/banner) at the end of the conversation with a retry button that calls `clearError()` and then `regenerate()`.

## Model switches and summaries

A [**Checkpoint**](/components/checkpoint) marks what happened between messages. To show a model switch, send the model with the start of every answer as message metadata, and show a checkpoint before an answer whose model differs from the answer before.

## Context usage

[**Context Usage**](/components/context-usage) shows how much of the model's context window is in use. Send the token usage with the end of every answer as message metadata and pass the `totalTokens` of the latest answer as `used`.
