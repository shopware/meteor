"@shopware-ag/meteor-component-library": minor
---

Removed the SCSS/Sass dependency from the component library. All styles are now plain, modern CSS: SCSS nesting became native CSS nesting (flattened at build time for older browsers), SCSS variables were replaced with meteor design tokens or inlined where they had a single use, and physical properties were switched to CSS logical properties where it makes sense. The elevation shadow color now comes solely from the synced design tokens (it is no longer pinned with `!important`, so it can follow the theme). The shipped CSS is now minified.

Visible changes from mapping legacy colors to semantic tokens (these spots also gain automatic dark-mode support): the disabled select option text is slightly lighter, the popover group action hover/pressed colors now darken instead of lighten, and the data table drag element uses the current brand palette. `src/assets/scss/` is no longer part of the package. The internal `mt-select-result` component lost its dead `description` slot and `descriptionPosition` prop (never fed by any select component, undocumented, and its bottom layout had been broken since the select redesign).

The data table's drag-state selectors (`thead th.is--dragging`, `table.is--dragging-inside`) are now scoped to `.mt-data-table` instead of matching any table on the page. Popovers and the data table no longer enforce their own hardcoded Inter stack with divergent OpenType features on every descendant — they now inherit the body typography like every other component, so glyphs inside them (e.g. zeros, punctuation spacing) match the rest of the UI. Additionally, five enter transitions (popover, select result list, select result, popover item result) were still using Vue 2 class names (`-enter`) and never played; they now use `-enter-from` and animate again. The data table filter button's hover rule dropped a `var(--color-icon-primary-hover)` declaration referencing a token that does not exist (the rendered color is unchanged).
