Fix `mt-select` rendering its label without associating it with the input. The `identification` generated by `mt-base-field` (the `name` attribute or a generated id) is now forwarded through the `#mt-select-selection` slot scope to `mt-select-selection-list`, which binds it as the search input's `id`. The `<label for="...">` association works again, so the select has an accessible name and clicking the label focuses the field. This also fixes the label association for everything built on `mt-select`, such as `mt-entity-select`, `mt-theme-select`, and the `mt-data-table` pagination select.
