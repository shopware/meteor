Add `MtApp`, an application shell for standalone Meteor applications. It arranges the `header`, `sidebar-start`, `content`, `sidebar-end` and `global` slots into the standard frame layout, and below the `mobileBreakpoint` (1280px by default, `0` disables it) both sidebars become off-canvas drawers with automatic header triggers, a backdrop, Escape and focus handling, while staying the same elements as on desktop so their state survives layout changes. The content panel is the only scroll container: the document stays locked through CSS (`lockDocument`), and with Vue Router the shell closes an open drawer on every navigation (`closeOnNavigate`), scrolls the content to the top on path changes, restores its scroll position on back and forward, and scrolls to URL hashes. The shell renders a "Skip to content" button, prints the content without the surrounding frame, and hydrates server-rendered markup without mismatches. It enables all future flags by default, with `future` applied on top (`{ removeCardWidth: false }` keeps all other flags enabled), controls the color theme through `v-model:theme`, `themeStorageKey` and `applyTheme`, mounts the `MtSnackbar` host itself, exposes its state and scroll container to descendants through the new `useMtApp()` composable, and lets views hide the header and sidebars through the new `useMtAppRegions()` composable, for example for fullscreen routes.

Alongside: `provideFutureFlags` accepts a ref or getter and then provides a reactive object, `hasSlotContent` treats lists that render only comments as empty, and `MtSnackbar` renders only its first mounted instance, so every notification appears once even when several hosts are mounted.
