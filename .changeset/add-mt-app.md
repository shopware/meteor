Add `MtApp`, an application shell for standalone Meteor applications. It arranges the `header`, `sidebar-start`, `content`, `sidebar-end` and `global` slots into the standard frame layout, and below the `mobileBreakpoint` (1280px by default, `0` disables it) both sidebars become `MtDrawer` drawers with automatic header triggers, a backdrop, Escape, swipe and focus handling, while their content is moved instead of re-mounted, so its state survives layout changes. `startDrawerVariant` and `endDrawerVariant` give a drawer the floating look. The content panel is the only scroll container: the document stays locked through CSS, and with Vue Router the shell closes an open drawer on every navigation, scrolls the content to the top on path changes, restores its scroll position on back and forward, and scrolls to URL hashes. The shell renders a "Skip to content" button, prints the content without the surrounding frame, and hydrates server-rendered markup without mismatches. It enables all future flags by default, with `future` applied on top (`{ removeCardWidth: false }` keeps all other flags enabled), applies the color theme persisted under `mt-theme` to `<html>`, mounts the `MtSnackbar` host itself, exposes its state and scroll container to descendants through the new `useMtApp()` composable, and lets views hide the header and sidebars through the new `useMtAppRegions()` composable, for example for fullscreen routes.

Alongside: `provideFutureFlags` accepts a ref or getter and then provides a reactive object, `hasSlotContent` treats lists that render only comments as empty, and `MtSnackbar` renders only its first mounted instance, so every notification appears once even when several hosts are mounted.
